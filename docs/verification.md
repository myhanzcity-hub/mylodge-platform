# 구현 검증 기록

2026-10-30, 로컬 루프백 미리보기 기준.

## 자동 검증

- 도메인 테스트: 19개 통과. 지분·예약·이용권·서비스·정비·상태 전이를 확인했다.
- 실제 로컬 D1 API: 7개 통과. 인증·Origin 차단, 영속화, 동일 요청의 동시 1회 처리, 중복 예약 차단, 변경 실패 시 원본 유지, 취소 중복 복구 차단, 납입·정산 선행 조건을 확인했다.
- Chromium 브라우저: **19개 전체 통과**, 최종 연속 실행 2.2분. 중간 실패를 남긴 상태로 완료 처리하지 않았다.
- 상담·파트너 입력의 초기 복원 경쟁을 고친 뒤 해당 두 시나리오를 각각 두 번 추가 실행해 4개 모두 통과했다.

브라우저 검증은 공개 24개 주소의 성공 응답과 제목, 검색·예산 단위·필터 복원, 팝업의 초점·스크롤·뒤로가기, 비교 상한, 납입 계산, 로그인 왕복 초안·선택 동의, 저장 영속화, 파트너·문의, 예약 변경·취소·초대·주문, 납입 확인과 정산, 미션·보상 재고, 정비와 영향 안내, 404 복구를 포함한다.

## 화면 확인

`outputs/qa/`의 로컬 캡처로 홈 데스크톱·390/320px, 별장 상세, 인테리어, 비용 화면을 확인했다. 회원 데스크톱과 운영자 390px도 별도 확인했다. 업무 화면 8개와 주요 공개 화면에서 문서 가로 넘침을 검사했다.

초기 렌더링 직후 입력이 사라질 수 있는 문제는 테스트의 대기 시간을 늘리는 대신 실제 컨트롤의 활성화 시점을 수정했다. 단지 중복 h1, 모달 복귀 위치, 상담의 선택 필드 null, 홈 예산 단위도 수정했다.

## 검증의 경계

- Windows 사용자 브라우저 연결은 사용할 수 없어, 저장소의 독립된 headless Chromium 회귀 검증과 캡처를 사용했다. 열린 개인 Chrome 탭을 조작하지 않았다.
- 320/390px 검증은 브라우저 viewport 검증이며 실제 휴대전화의 감각·터치·네트워크 검수와 구분한다.
- 실제 전자서명·등기·결제·송금·외부 발송과 실회원 간 교환은 실행하지 않았다.
- hosted 로그인 이후의 실제 사용자 E2E는 이 로컬 테스트 결과에 포함하지 않는다. 배포 성공은 Sites의 최종 반환 상태로 별도 확인한다.
- 실제 사용자 Core Web Vitals의 75백분위는 아직 측정하지 않았다.
- 실제 운영자 멤버십·전역 재고·다중회원 업무에 대한 검증 결과가 아니다. 현재는 인증된 사용자별 체험 데이터에 대한 결과다.

실행 명령과 운영 전환 기준은 README.md와 implementation-status.md에 있다.
