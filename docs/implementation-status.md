## 운영 데이터와 체험 데이터의 경계

현재 `mode`는 서버에서 `preview`로 고정한다. 회원·파트너·운영 화면은 한 사용자의 격리된 샌드박스를 서로 다른 업무 관점으로 보여준다. 계정별 데이터는 D1에 영속 저장하며 다른 사용자의 기록을 읽거나 바꿀 수 없다.

가상 운영 화면 진입이 실제 조직의 운영자 권한을 부여하는 것은 아니다. 실제 조직의 역할별 멤버십, 담당 단지·고객 범위, 작성·승인 분리, 별도 관리자 초대 정책은 운영 전환 작업이다. 전역 객실·지분 재고와 실제 회원 간 교환도 운영 모드용 관계형 모델과 별도 검증이 필요하다.

현재 체험 원장은 사용자별 aggregate와 버전으로 저장한다. 모든 상태 변경을 CAS·D1 batch로 함께 처리하며 요청 영수증을 별도 테이블에 보존한다. 고객·금액·권리 등의 실제 운영 원장으로 즉시 전환할 수 있다고 주장하지 않는다.

## 실제 외부 처리를 하지 않는 항목

- 법적 전자계약·서명과 부동산 등기.
- 실제 결제, 입금 대사, 환불, 파트너 송금.
- 문자·메일·메신저 발송과 외부 고객센터 접수.
- 실제 타 회원 예약의 교환, 외부 숙박 플랫폼 판매.
- 승인 도면·확정 주소·개장 상태·실제 분양 가능성 증명.
- 실제 재생할 영상 파일. 파일이 없으므로 재생 버튼을 가장하지 않고 이미지 투어를 제공한다.

`liveContracts`, `livePayments`, `livePayouts`, `liveRentals`는 false다. 외부 처리 결과 없이 완료 상태를 표시하지 않는다.

## 사업자가 확정할 항목

1. 소유 대상·권리 형태·계약 당사자·실제 서명과 권리 확인 절차.
2. 가격·세금·등기·옵션·공과금·수선·청소비의 포함/별도·필수/선택.
3. 승인 면적·인원·도면·시설과 단지별 사업·개장 상태.
4. 연 360박 공급과 정비·재난·고장에 대한 대체·이월·환급 책임.
5. 이용연도·개장 첫해·예약 개방·성수기·주말·추첨·대기 규칙.
6. 변경·취소·노쇼·서비스 취소와 이용권 복구·환급 기준.
7. 지인 이용·교환·양도·상속의 권리·예약·미납 승계.
8. 추천 귀속·미션·그룹핑 보상·중복·재고 부족·환수 기준.
9. 납입·정산 증빙, 정산 주기·공제·지급 승인·제공자.
10. 개인정보 처리 주체·보관·파기·문의·계정 복구와 운영 약관.

체험 정책은 기능 검증을 위한 값이며 실제 고객과의 약정이 아니다. 원자료의 관리비·청소비, 면적, 옵션 16만 원과 총 2,000만 원 차이, 등기 대상 등은 최종 사업 조건으로 정리해야 한다.
